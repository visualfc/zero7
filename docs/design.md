# 零七设计文档

> 本文描述零七（ZERO7）的系统边界、核心数据流和交互约束。实现发生变化时，应同步更新本文。

## 1. 设计目标

零七是一款面向象棋初学者和普通爱好者的中文语音象棋应用。设计重点如下：

1. 象棋规则由本地规则引擎决定，语音模型不直接决定棋局是否合法。
2. 语音操作必须有明确的开始、结束和失败反馈。
3. 人机对战中，棋盘状态、棋谱、动画和语音说明保持一致。
4. 没有实体灵矽硬件时，允许使用虚拟设备和本地桥接服务。
5. 手机浏览器通过安全的 HTTPS 上下文访问麦克风。
6. 所有关键交互都可以通过自动化测试验证。

## 2. 系统架构

```text
┌──────────────────────────────┐
│ 浏览器 React 应用              │
│ - 训练页                       │
│ - 人机对战页                   │
│ - 棋盘、棋谱和动画             │
│ - 语音按住/松开交互            │
└──────────────┬───────────────┘
               │ HTTP / WebSocket
               ▼
┌──────────────────────────────┐
│ 本地 Express 灵矽桥接服务       │
│ - 注入认证信息                  │
│ - 转发语音事件                  │
│ - 代理 Pikafish 请求            │
└───────┬──────────────┬─────────┘
        │              │
        ▼              ▼
┌──────────────┐  ┌──────────────┐
│ 灵矽服务       │  │ Pikafish     │
│ STT / LLM /  │  │ UCI 子进程    │
│ TTS           │  │ 正式棋力      │
└──────────────┘  └──────────────┘
```

### 2.1 浏览器应用

`src/App.tsx` 负责页面导航、训练状态、人机对战状态和用户输入。棋盘组件只负责渲染棋盘和接收格子点击，棋局状态由 `Chess` 实例保存。

`src/App.css` 负责响应式布局、棋盘样式、棋子样式、走棋动画和手机端语音按钮。

### 2.2 规则和对战模块

- `src/chess.ts`：棋盘坐标、棋子显示、走法文本和训练规则辅助函数。
- `src/battle.ts`：创建对局、合法走法、基础 AI、棋谱和对局状态。
- `src/battle-rules.ts`：集中管理品牌名称、语音文案、思考延迟、动画时长和红黑双方通用讲解规则。
- `src/pikafish.ts`：调用服务端 Pikafish API。

### 2.3 灵矽语音模块

`src/linxi.ts` 封装灵矽 WebSocket、浏览器录音和 TTS 播放。`src/audio-player.ts` 将 16 kHz PCM16 音频送入 Web Audio 播放。

认证信息只在本地桥接服务和服务端环境中处理，浏览器不保存敏感凭证。

## 3. 语音交互设计

### 3.1 按住识别、松开完成

语音按钮和空格快捷键遵循相同规则：

1. 按下后建立一次临时灵矽连接并开始录音。
2. 按住期间显示“松开完成”。
3. 松开后提交当前录音。
4. 收到识别结果后处理一次指令并释放连接。
5. 短按少于最短按住时间时取消本次识别。
6. 失败时恢复“按住说走法”，并显示失败原因。

每次语音指令使用一次连接。应用不维持语音长连接，也不会因断线自动建立后台连接。

### 3.2 语音结果分类

识别结果分为两类：

- 能识别为棋步，但当前局面不能执行：
  - 页面和语音提示“这步棋现在不能走，请重新说当前局面可以走的走法”。
  - 不执行落子，不播放后续棋局评论。
- 没有识别成棋步：
  - 页面和语音提示“没听明白，请重新说”。
  - 不改变棋局。

识别到合法走法后，规则引擎负责最终校验，语音模型不能绕过合法性检查。

### 3.3 空格键

页面全局拦截空格的 `keydown`、`keypress` 和 `keyup` 默认行为：

- 防止页面滚动。
- 防止按钮触发默认点击。
- 首次 `keydown` 开始识别，重复 `keydown` 不重复建立连接。
- `keyup` 完成识别。

## 4. 人机对战回合时序

红方和黑方使用同一套走子、吃子、将军和将死讲解规则，区别只在操作者名称和被吃棋子的颜色。

### 4.1 用户走子

```text
用户落子
  ↓
规则引擎确认合法
  ↓
更新棋盘、棋谱、路径和动画
  ↓
播放用户走子说明
  ↓
如果吃子，播报具体棋子，例如“吃掉了黑车”
```

非法走法不会进入后续流程。

### 4.2 AI 应手

```text
用户语音说明播放完成
  ↓
等待 2 秒，模拟思考
  ↓
请求 Pikafish 或使用基础 AI
  ↓
规则引擎确认 AI 走法确实落子
  ↓
更新棋盘、棋谱、路径和动画
  ↓
播放“零七应对……”
```

AI 返回无效走法时，不更新棋盘，也不播放与实际局面不一致的评论。

### 4.3 吃子说明

双方使用具体棋子名称：

| 被吃方 | 棋子示例 |
| --- | --- |
| 红方 | 红帅、红仕、红相、红马、红车、红炮、红兵 |
| 黑方 | 黑将、黑士、黑象、黑马、黑车、黑炮、黑卒 |

示例：

```text
你走车二进九，吃掉了黑车。
零七应对车一平二，吃掉了红车。轮到你继续走棋。
```

## 5. 棋盘反馈

- 最近一步显示起点到终点的路径。
- 红方路径使用红色，黑方路径使用深蓝色。
- 路径显示 2 秒后消失。
- 对方下一步走子时，路径立即替换。
- 吃子位置显示独立的吃子动画。
- 悔棋、重开、返回当前局面和复盘切换会清理或更新路径。
- 动画只影响显示，不改变规则引擎状态。

## 6. 手机端和 HTTPS

浏览器调用麦克风需要安全上下文。开发环境使用 `mkcert` 生成本地证书：

```bash
brew install mkcert
mkcert -install
npm run dev
```

证书文件位于本地 `.cert/`，不会提交到 Git。电脑和手机连接同一 Wi-Fi 后，手机访问终端输出的局域网地址，例如：

```text
https://192.168.1.45:5173/
```

手机还需要安装并信任 `mkcert` 根证书。根证书位置可以用下面的命令查看：

```bash
mkcert -CAROOT
```

如果通过 HTTP 访问，应用会提示使用 HTTPS。证书不受信任时，浏览器会显示 `ERR_CERT_AUTHORITY_INVALID`，并可能拒绝麦克风权限。

## 7. 测试和质量门槛

测试分为以下几类：

- `src/*.test.ts`：棋盘规则、对战规则、灵矽客户端、音频播放和 Pikafish。
- `src/App.test.tsx`：页面导航、语音按钮、空格快捷键、人机对战、复盘、悔棋和错误状态。
- `server/pikafish.node-test.mjs`：服务端 Pikafish 行为。

运行完整检查：

```bash
npm run lint
npm test
npm run test:coverage
npm run build
```

当前 Vitest 全局覆盖率门槛：

| 指标 | 最低要求 |
| --- | ---: |
| Statements | 90% |
| Branches | 80% |
| Functions | 90% |
| Lines | 90% |

Codecov 的 Pull Request Patch 覆盖率目标为 80%。新增功能应补充正常流程、错误流程和边界状态测试。

## 8. 安全边界

- `.env`、设备标识、客户端标识、Token 和 API Key 不提交到 Git。
- `.cert/` 中的开发私钥不提交到 Git。
- 浏览器不能直接决定棋步是否合法。
- 识别失败和非法走法不能触发 AI 评论。
- 过期的 AI 请求不能覆盖新棋局。
- 页面切换和主动断开必须清理录音、WebSocket 和定时器。

## 9. 文档关系

`README.md` 面向用户和贡献者，说明产品能力、安装配置和常用操作。本文面向开发者，说明模块边界、运行时规则和状态时序。新增功能时先更新设计文档中的规则，再同步 README 中的用户可见能力和使用步骤。

## 10. 变更原则

涉及棋局状态时，必须同时检查棋盘、棋谱、回合状态、语音说明、动画、复盘和悔棋。涉及手机端语音时，必须检查 HTTPS、安全上下文、麦克风权限和长按手势。涉及覆盖率时，必须运行 `npm run test:coverage`，不能通过降低门槛隐藏未覆盖代码。
