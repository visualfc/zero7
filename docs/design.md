## 当前版本边界

当前版本以本地浏览器、Express 桥接服务、SQLite 数据库和本地 Pikafish 为核心。页面状态保存在当前会话中，训练题和经典棋局由服务端按需查询；账号、云端同步、远程分析队列和在线排行榜不属于当前实现。

## 1. 设计目标

零七是一款面向象棋初学者和普通爱好者的中文语音象棋应用。设计重点如下：

1. 象棋规则由本地规则引擎决定，语音模型不直接决定棋局是否合法。
2. 语音操作必须有明确的开始、结束和失败反馈。
3. 人机对战中，棋盘状态、棋谱、动画和语音说明保持一致。
4. 没有实体灵矽硬件时，允许使用虚拟设备和本地桥接服务。
5. 手机浏览器通过安全的 HTTPS 上下文访问麦克风。
6. 所有关键交互都可以通过自动化测试验证。

## 2. AI 复盘与经典对局

AI 复盘整合在人机对战页底部。进入复盘后暂停人机落子和回合语音提醒，左侧显示可滚动的完整中文棋谱，中间棋盘保持最大可用尺寸，右侧显示经典棋局选择和分析控制；“返回对战”恢复原人机局面。

经典棋局从 Wukong Xiangqi `xqdb` 导入 2,000 盘完整大师对局。仅保留红黑双方中文姓名都经过权威资料确认的棋局；未确认姓名的棋局不导入。SQLite 列表接口分页返回赛事和棋手元数据，选中后才加载完整 UCI 着法。当前来源未为全部棋局提供可核验赛果，因此界面暂不显示胜负结果。

复盘支持开局、上一步、下一步、终局和每 5 秒自动播放。自动播放异步播报每一步中文棋谱。当前局面分析显示红黑胜率、实战着及推测目的；第 3 步起，实战着与引擎首选不同时显示推荐着及目的。全局分析使用 30 秒预算的两阶段流程：快速扫描整盘，再深度复核候选关键步。局面分析与全局分析使用独立请求，切步不会中止全局分析；切换棋局或返回对战才取消全局任务。关键步按棋谱顺序显示在棋盘右侧。

## 3. 系统架构

```text
┌──────────────────────────────┐
│ 浏览器 React 应用              │
│ - 训练页                       │
│ - 人机对战页                   │
│ - 棋盘、棋谱和动画             │
│ - 语音按住/松开交互            │
└──────────────┬───────────────┘
               │ HTTP / WebSocket
               ▼
┌──────────────────────────────┐
│ 本地 Express 灵矽桥接服务       │
│ - 注入认证信息                  │
│ - 转发语音事件                  │
│ - 代理 Pikafish 请求            │
│ - 提供 SQLite 题库查询 API       │
└───────┬──────────┬─────────────┘
        │          │
        ▼          ▼
┌──────────────┐  ┌──────────────┐
│ 灵矽服务       │  │ Pikafish     │
│ STT / LLM /  │  │ UCI 子进程    │
│ TTS           │  │ 正式棋力      │
└──────────────┘  └──────────────┘

JSON 题库源数据 → 校验导入 → SQLite 运行时数据库
```

### 3.1 浏览器应用

`src/App.tsx` 负责页面导航、训练状态、人机对战状态和用户输入。棋盘组件只负责渲染棋盘和接收格子点击，棋局状态由 `Chess` 实例保存。

`src/App.css` 负责响应式布局、棋盘样式、棋子样式、走棋动画和手机端语音按钮。

### 3.2 规则和对战模块

- `src/chess.ts`：棋盘坐标、棋子显示、走法文本和训练规则辅助函数。
- `src/battle.ts`：创建对局、合法走法、基础 AI、棋谱和对局状态。
- `src/battle-rules.ts`：集中管理品牌名称、语音文案、思考延迟、动画时长和红黑双方通用讲解规则。
- `src/pikafish.ts`：调用服务端 Pikafish API。
- `src/puzzles.ts`：题库 API 客户端、FEN 到界面棋子的转换和浏览器端答案复核。
- `server/puzzle-database.mjs`：JSON 校验、SQLite 导入和分页查询仓库。
- `scripts/import-puzzles.mjs`：手动重建运行时 SQLite 题库。

### 3.3 练习题库

练习题库使用“JSON 源数据 + SQLite 运行时数据库”两层结构：

```text
data/puzzles/sources.json
        +
data/puzzles/wukong.json
        ↓ 导入时校验 FEN、来源、答案和提示
server/data/puzzles.sqlite
        ↓ GET /api/puzzles
浏览器训练状态
```

约束如下：

1. JSON 是唯一人工维护且提交 Git 的题库数据。
2. SQLite 是自动生成的运行时产物，不提交 Git。
3. 后端启动时发现数据库缺失或 JSON 更新会自动重建。
4. 每道题保存 Wukong 原始 ID、完整六字段 FEN、结构化走法、来源和许可证。
5. 当前从 1,061 个一步杀候选中筛出 969 个一步杀局面、1,018 个二步杀局面、762 个三步杀局面、361 个四步杀局面和 184 个 N 步杀局面，并导入棋弈江湖 7,346 道带 `bestMove` 的残局题。
6. Wukong 题和棋弈江湖残局题使用不同训练模式；残局题的 `bestMove` 只是推荐首着，不能直接完成题目。
7. 残局模式的每一步都使用与人机对弈相同的合法着和 Pikafish 应手流程，真实终局才结束题目。
8. 中文标题、分级提示和反馈由 ZERO7 生成，来源局面遵循各自许可证。
9. ChessDB 只通过可审计的离线报告补充校验状态、评分和最佳着，不作为训练运行时的在线依赖。

查询接口：

- `GET /api/puzzles?offset=0&limit=50`
- 可选 `source` 和 `difficulty` 参数。
- `GET /api/puzzles/:id` 查询单题。
- 题目记录可包含 `sourceBestMove`、`sourceResult`、`sourceType` 和 `chessdb` 校验字段。

### 3.4 灵矽语音模块

`src/linxi.ts` 封装灵矽 WebSocket、浏览器录音和 TTS 播放。`src/audio-player.ts` 将 16 kHz PCM16 音频送入 Web Audio 播放。

认证信息只在本地桥接服务和服务端环境中处理，浏览器不保存敏感凭证。

## 4. 语音交互设计

### 4.1 按住识别、松开完成

语音按钮和空格快捷键遵循相同规则：

1. 按下后建立一次临时灵矽连接并开始录音。
2. 按住期间显示“松开完成”。
3. 松开后提交当前录音。
4. 收到识别结果后处理一次指令并释放连接。
5. 短按少于最短按住时间时取消本次识别。
6. 失败时恢复“按住说走法”，并显示失败原因。

每次语音指令使用一次连接。应用不维持语音长连接，也不会因断线自动建立后台连接。

### 4.2 语音结果分类

识别结果分为两类：

- 能识别为棋步，但当前局面不能执行：
  - 页面和语音提示“这步棋现在不能走，请重新说当前局面可以走的走法”。
  - 不执行落子，不播放后续棋局评论。
- 没有识别成棋步：
  - 页面和语音提示“没听明白，请重新说”。
  - 不改变棋局。

识别到合法走法后，规则引擎负责最终校验，语音模型不能绕过合法性检查。

### 4.3 空格键

页面全局拦截空格的 `keydown`、`keypress` 和 `keyup` 默认行为：

- 防止页面滚动。
- 防止按钮触发默认点击。
- 首次 `keydown` 开始识别，重复 `keydown` 不重复建立连接。
- `keyup` 完成识别。

## 5. 训练回合时序

### 5.1 初始化与导航

训练页面从 `/api/puzzles` 加载 SQLite 中的题目，并用 FEN 创建独立 `Chess` 实例。题目徽标显示“红方先行”或“黑方先行”，不在界面显示题库来源名称。用户可以随时：

- 点击“重新练习”恢复原始 FEN；
- 点击“跳过这题”进入下一题；
- 完成后点击“挑战下一关”或“继续下一题”。

切题或重置会增加请求序号。旧的 Pikafish 响应到达时，如果请求序号或 `Chess` 实例不匹配，则直接丢弃，不能覆盖新局面。

### 5.2 普通合法着

```text
用户点击或语音走出合法着
  ↓
本地 Chess 实例执行走法
  ↓
请求 Pikafish 计算对方应手
  ↓
规则引擎再次执行并确认应手合法
  ↓
更新棋盘，轮到用户继续走
```

非法着不执行。Pikafish 失败时保留用户走法，并允许重新练习或跳过。

### 5.3 绝杀验证

标准答案只是候选答案，坐标匹配不能直接成功：

```text
用户走出候选着或其他形成将死的合法着
  ↓
本地规则检查 isCheckmate()
  ↓
Pikafish 检查走后局面
  ├─ 返回合法应手：执行应手并继续棋局
  ├─ 验证失败：不判成功，允许重练或跳过
  └─ 返回 bestmove (none) 且本地确认将死：判定绝杀
```

确认绝杀后界面显示“绝杀！”和着法，语音播报“车五进一，绝杀！”。界面不展示 Pikafish 的内部终局返回信息。

### 5.4 题目选择

训练页提供“杀棋类型”和“选择题目”两个下拉菜单。类型菜单包含一步杀、二步杀、三步杀、四步杀和 N 步杀；题目菜单只列出当前类型。题号分别从 `1001`、`2001`、`3001`、`4001` 和 `9001` 开始。切换类型会打开该类型第一题。残局页提供“残局类型”和“选择题目”两个下拉菜单，按进攻方主要子力分为车类残局、马炮残局、炮类残局、马类残局、兵类残局和仕相残局，车类、马炮、炮类、马类、兵类和仕相残局分别从 `10001`、`20001`、`30001`、`40001`、`50001` 和 `60001` 开始编号。精确子力对型继续显示在题目标题中。切换题目会恢复原始 FEN，并取消旧的引擎请求和待播放走棋语音。

### 5.5 提示与语音

- 提示分三级，只显示和朗读提示，不自动落子或完成题目。
- 每次提示朗读创建独立短时 TTS 连接，播放结束立即断开。
- 人机、训练和残局的 TTS 与棋局状态完全异步。用户落子后立即并行提交语音和引擎请求；引擎应手只等待固定思考延迟，不等待 `speakText` 或 `waitForPlayback`。黑棋落子后语音独立排队播放，语音卡住或失败不影响走棋、终局判断和分析更新。
- 用户落子后立即显示己方走子路径；用户走法朗读完成后等待 2 秒，再执行 Pikafish 应手并切换为对方走子路径。路径沿用人机对战的红黑样式和显示时长。引擎普通应手只显示“零七走了某步。”并朗读实际棋步；应手形成将军时显示和朗读“某步，将军。”。终局按“闷杀、绝杀、困毙杀”分类：将死且被将方的将/帅在九宫内所有相邻退路均被己方棋子封住时为闷杀；其他被将军且无合法应手的局面为绝杀；未被将军但无合法着的局面为困毙杀。不评价用户走法，不提示继续尝试或重新练习。
- 残局页提供可展开和收起的引擎讲解。展开时调用 Pikafish 分析模式生成推荐中文棋步、局面评分和行动建议；用户走棋、黑棋应手或切换题目后自动基于最新 FEN 更新。收起后停止自动更新。语音按钮按需朗读当前讲解，自动刷新不会打断逐步走棋播报。
- 切换训练或残局题时，客户端调用 `/api/pikafish/warmup`，服务端对题目初始 FEN 执行 100 ms 普通搜索，用于启动进程、加载 NNUE 和预热哈希。预热结果不改变棋盘，切题时取消旧的客户端请求，预热失败不显示页面错误。
- 每个合法着都必须获得引擎应对。一步杀使用有时间上限的普通搜索确认终局；多步杀使用带 `movetime` 上限的 `go mate N`，没有返回走法或搜索失败时立即回退 Pikafish 普通搜索。任何 UCI 命令超时都会终止并重建引擎进程，旧进程退出事件不能清理新进程，避免后续请求持续卡在 `isready`。普通搜索也失败时提示“引擎连接失败，请重试”，棋局停留在用户走后局面。
- 最后一着由“棋步，绝杀！”或“棋步，困毙杀！”统一播报，避免重复朗读。
- 切题或重新练习会取消当前题目的待播放走棋语音。
- 训练按钮和空格都遵循按住建立连接、松开识别、处理后断开的短连接规则。
- 红方题与黑方题都根据 FEN 的行棋方限制可选棋子。

## 6. 人机对战回合时序

红方和黑方使用同一套走子、吃子、将军和将死讲解规则，区别只在操作者名称和被吃棋子的颜色。

### 6.1 用户走子

```text
用户落子
  ↓
规则引擎确认合法
  ↓
更新棋盘、棋谱、路径和动画
  ↓
播放用户走子说明
  ↓
如果吃子，播报具体棋子，例如“吃掉了黑车”
```

非法走法不会进入后续流程。

### 6.2 AI 应手

```text
用户语音说明播放完成
  ↓
等待 2 秒，模拟思考
  ↓
请求 Pikafish 或使用基础 AI
  ↓
规则引擎确认 AI 走法确实落子
  ↓
更新棋盘、棋谱、路径和动画
  ↓
播放“零七应对……”
```

AI 返回无效走法时，不更新棋盘，也不播放与实际局面不一致的评论。

### 6.3 吃子说明

双方使用具体棋子名称：

| 被吃方 | 棋子示例 |
| --- | --- |
| 红方 | 红帅、红仕、红相、红马、红车、红炮、红兵 |
| 黑方 | 黑将、黑士、黑象、黑马、黑车、黑炮、黑卒 |

示例：

```text
你走车二进九，吃掉了黑车。
零七应对车一平二，吃掉了红车。轮到你继续走棋。
```

## 7. 棋盘反馈

- 最近一步显示起点到终点的路径。
- 红方路径使用红色，黑方路径使用深蓝色。
- 路径显示 2 秒后消失。
- 对方下一步走子时，路径立即替换。
- 吃子位置显示独立的吃子动画。
- 悔棋、重开、返回当前局面和复盘切换会清理或更新路径。
- 动画只影响显示，不改变规则引擎状态。

## 8. 手机端和 HTTPS

浏览器调用麦克风需要安全上下文。开发环境使用 `mkcert` 生成本地证书：

```bash
brew install mkcert
mkcert -install
npm run dev
```

证书文件位于本地 `.cert/`，不会提交到 Git。电脑和手机连接同一 Wi-Fi 后，手机访问终端输出的局域网地址，例如：

```text
https://192.168.1.45:5173/
```

手机还需要安装并信任 `mkcert` 根证书。根证书位置可以用下面的命令查看：

```bash
mkcert -CAROOT
```

如果通过 HTTP 访问，应用会提示使用 HTTPS。证书不受信任时，浏览器会显示 `ERR_CERT_AUTHORITY_INVALID`，并可能拒绝麦克风权限。

- `src/*.test.ts`：棋盘规则、对战规则、灵矽客户端、音频播放和 Pikafish。

- `server/pikafish.node-test.mjs`：服务端 Pikafish 走法和 `bestmove (none)` 终局解析。

运行完整检查：

npm run lint

## 10. 安全边界

- `.env`、设备标识、客户端标识、Token 和 API Key 不提交到 Git。
- `.cert/` 中的开发私钥不提交到 Git。
- 浏览器不能直接决定棋步是否合法。
- 识别失败和非法走法不能触发 AI 评论。
- 过期的 AI 请求不能覆盖新棋局。
- 页面切换和主动断开必须清理录音、WebSocket 和定时器。

## 11. 文档关系

`README.md` 面向用户和贡献者，说明产品能力、安装配置和常用操作。本文面向开发者，说明模块边界、运行时规则和状态时序。新增功能时先更新设计文档中的规则，再同步 README 中的用户可见能力和使用步骤。

## 12. 变更原则

涉及棋局状态时，必须同时检查棋盘、棋谱、回合状态、语音说明、动画、复盘和悔棋。涉及手机端语音时，必须检查 HTTPS、安全上下文、麦克风权限和长按手势。涉及覆盖率时，必须运行 `npm run test:coverage`，不能通过降低门槛隐藏未覆盖代码。
