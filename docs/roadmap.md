# ZERO7 路线图

> 路线图描述产品未来方向，不代表功能已经实现。每个阶段完成前，必须同步更新 README、设计文档、测试和第三方声明。

## 路线图原则

1. 先保证棋局正确、语音可靠和数据可追溯，再增加产品范围。
2. 所有新功能都必须有明确的数据边界、失败状态和取消机制。
3. 影响棋局状态的功能必须保持棋盘、棋谱、引擎请求、TTS 和页面导航一致。
4. 新增用户可见能力前，先补充自动化测试；覆盖率继续保持 Statements、Functions、Lines ≥90%，Branches ≥80%，Codecov Patch ≥80%。
5. 外部数据必须保留来源、许可证、原始标识和校验记录，未确认的信息不进入展示层。

## 当前版本基线

已完成的核心能力：

- 人机对战：点击和中文语音走棋、初级/中级/高级/大师四档棋力、悔棋、认输、重开和异步 TTS。
- 杀棋训练：一步杀至 N 步杀，按类型和题号选择，支持红方先行和黑方先行；合法着由大师级引擎应手。
- 残局训练：六类残局、大师级引擎应手、可展开的引擎讲解和中文语音。
- AI 复盘：整合在人机对战页，支持 2,000 盘经典完整棋局、逐步回放、当前局面分析和全局关键步分析。
- 分析：局面分析、残局讲解、复盘分析和全局关键步均使用大师棋力。
- 语音：人机、训练和残局共用讲解面板；中文棋谱按读音匹配，识别后在同一会话播放 TTS。
- 数据层：JSON 源数据、SQLite 运行时查询、题库校验和经典棋局按需加载。
- 工程质量：自动化测试、覆盖率检查、生产构建和 GitHub Actions。

## 阶段一：稳定性与质量（近期）

目标是让现有功能适合持续使用和持续开发。

- 补齐 Codecov Patch 覆盖率缺口，重点覆盖 `App.tsx` 的异常、取消和边界分支。
- 清理 React 测试中的 `act(...)` 警告，降低异步测试的维护成本。
- 增加真实浏览器回归流程：人机走子、训练应手、残局讲解、经典棋局加载和页面返回。
- 统一错误提示、重试按钮和网络中断后的恢复行为。
- 为引擎请求、语音请求和复盘分析增加统一的超时、取消和日志标识。
- 继续压缩文档图片和构建产物，保证仓库资源适合在线浏览。

完成标准：核心用户流程有端到端测试；引擎、语音和数据库失败都能恢复；质量门槛稳定通过。

## 阶段二：内容与分析增强（中期）

目标是提升训练内容的覆盖范围和讲解质量。

- 扩充经过确认的经典棋局，并记录棋手身份、赛事、来源和校验状态。
- 增加更多可审计的杀棋和残局来源，保持题型、难度和原始编号可追溯。
- 优化多步将杀的目标深度、时间预算和失败回退策略。
- 改进走棋目的推测：结合将军、吃子、子力活动、攻守转换和关键防守等可解释标签。
- 在全局分析中增加关键步前后的局面摘要，并保持关键步按棋谱顺序显示。
- 为经典棋局补充可信赛果和开局标签；来源没有可靠信息时继续隐藏字段。

完成标准：新增内容通过来源审查、合法着回放和代表性人工复核；分析结果能解释依据，不能把引擎原始分数直接当作结论。

## 阶段三：语音与学习体验（中期）

目标是让语音操作在不同设备和不同使用习惯下更稳定。

- 增加语音识别结果的可编辑确认，让用户在嘈杂环境下修正棋步。
- 增加方言、连读和方位词的补充纠错，并继续保留本地合法着校验。
- 增加语音音量、语速和自动播报开关，同时保持 TTS 异步，不阻塞棋局。
- 为训练题增加可选的分步解释、错着复盘和完成后的关键变化回看。
- 增加无障碍支持：键盘焦点顺序、屏幕阅读器标签、颜色以外的走子路径提示。
- 优化手机端弱网、麦克风权限拒绝和 HTTPS 证书提示。

完成标准：语音失败可以转为点击操作；所有语音开关都有明确状态；键盘和屏幕阅读器可以完成主要流程。

## 阶段四：个人化与跨设备（远期）

这些能力会改变数据和隐私边界，只有在本地体验稳定后再评估。

- 本地学习记录：完成题目、错误类型、训练历史和难度偏好。
- 可选的本地导出和导入，用于迁移训练进度和自定义题目。
- 用户自定义棋局导入，支持经过校验的 FEN、PGN/UCI 棋谱和隐私提示。
- 训练计划和复习提醒，默认使用本地数据，不默认上传对局内容。
- 多设备同步或账号体系，仅在明确设计数据保留、删除、加密和服务成本后实现。
- 可选的服务端分析队列，避免把本地 Pikafish 和灵矽凭证暴露给浏览器。

完成标准：先完成隐私设计、数据迁移格式和删除机制，再实现界面；个人数据和第三方服务凭证分离存储。

## 暂不纳入路线图

- 未经确认的棋手姓名自动音译或猜测。
- 没有来源和许可证记录的外部棋库。
- 直接用语音识别结果绕过规则引擎落子。
- 依赖 TTS 播放完成才能推进棋局的流程。
- 没有测试、取消机制和失败状态的后台长任务。
- 以“成长页面”作为独立功能入口；如果未来重新设计，必须先明确真实用户价值和数据来源。
